# AI_GUARDRAILS.md

This document defines the core constraints, verification protocols, and operating boundaries for all AI assistants, autonomous coding agents, and team members contributing to this repository. Because this project works directly on `main` without PR reviews or feature branches, all agents must treat these rules as non-negotiable operational boundaries[cite: 1].

---

## 1. Single Source of Truth: The Contract is Law
All AI agents must respect schema definitions before generating any interface, model, mock, or integration code:
* **Pre-Execution Check:** Always inspect and read `contracts/waypoint.schema.json`, `contracts/trivia-passport.schema.json`, and `contracts/api-openapi.yaml` before producing or consuming data[cite: 1].
* **Schema Invariance:** Never invent fields, alter property names, or modify data types to resolve local implementation hurdles[cite: 1].
* **Explicit Modification Workflow:** 
  * If a contract change is strictly necessary, treat it as an isolated issue and a standalone commit[cite: 1].
  * The contract change must precede dependent code changes and be explicitly documented in `docs/DECISIONS.md`[cite: 1].
  * Never quietly patch, overload, or bypass a schema mismatch locally[cite: 1].
* **Conflict Resolution:** If integration fails due to data shape mismatches, always refactor the code to adhere to `contracts/`. The contract always wins over implementation[cite: 1].

---

## 2. Commit Discipline: Direct-to-Main Workflow
Because development occurs straight to `main`, every AI action must adhere to strict git hygiene:
* **Atomic Linkage:** One issue = one commit[cite: 1]. Every commit message must reference its issue identifier (e.g., `feat(#4): audio capsule UI [iter3]`) and explicitly state which Definition of Done (DoD) criteria it satisfies[cite: 1].
* **Mandatory Sync Before Push:** Execute `git pull` (or `git pull --rebase`) immediately prior to pushing[cite: 1]. Do not rely on pull operations done at the start of a session[cite: 1].
* **Scope Isolation:** Keep commits small and focused[cite: 1]. If a task requires touching files in another domain's directory, declare it explicitly in the commit message and alert domain owners[cite: 1].
* **No History Rewrites:** Force-pushing (`git push --force`) is strictly banned[cite: 1]. Fix any regressions forward with a clear, incremental commit[cite: 1].

---

## 3. Style & Tooling Enforcements
All AI-generated code must adhere to unified tooling standards committed to the repository root:
* **Frontend:** Strict adherence to the shared ESLint + Prettier configurations (enforcing import orders, quoting, and naming patterns)[cite: 1].
* **Backend:** Strict adherence to the shared Ruff/Black configuration using standard `snake_case` patterns throughout[cite: 1].
* **Conventions:** Follow file and component naming patterns defined in `docs/CONVENTIONS.md`[cite: 1].
* **Zero-Tolerance Quality Gate:** Any AI-generated code failing local linting or formatting checks must not be pushed[cite: 1].

---

## 4. Hallucination & Placeholder Containment
AI models frequently invent plausible placeholder data or historical facts[cite: 1]. The following policies must be enforced:
* **Loud Placeholders:** Any mock data, simulated URL, or fallback value generated by an AI must be explicitly flagged with a `PLACEHOLDER_` prefix, an annotated `// TODO: verify` comment, or a logged entry in `docs/DECISIONS.md`[cite: 1].
* **Historical & Cultural Authenticity:** For cultural preservation components (e.g., Memory Vault, Audio Capsules), historical dates, claims, and media attributions must never be fabricated[cite: 1]. All cultural and factual content must map to verified, traceable sources before shipping[cite: 1].

---

## 5. Pre-Push Verification Checklist
Before any commit is pushed to `main`, the executing agent/engineer must run this operational check[cite: 1]:

- [ ] Matches the linked issue's Definition of Done (DoD)[cite: 1]
- [ ] Leaves `contracts/` untouched unless contract modification was the sole objective[cite: 1]
- [ ] Passes shared linters and formatters without warnings or errors[cite: 1]
- [ ] Contains at least one unit or smoke test covering the new endpoint or component[cite: 1]
- [ ] Map/UI components manually verified at a mobile viewport width[cite: 1]
- [ ] Zero secrets, private keys, environment variables, or test credentials committed[cite: 1]
- [ ] `git diff` reviewed end-to-end to confirm zero unintended file modifications[cite: 1]

---

## 6. Architectural Decision Logging
Chat history and prompt logs are volatile and unshared[cite: 1]. Every architectural choice, technical trade-off, third-party library selection, or temporary workaround must be permanently recorded:
* Add a one-line dated entry into `docs/DECISIONS.md`[cite: 1].
* Document dependencies, placeholder deployments, or relaxed configurations (e.g., rate-limit changes, spatial analysis library choices) so parallel agent sessions do not duplicate or reverse decisions[cite: 1].
